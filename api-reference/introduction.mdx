| What you are building | API and credentials |
| --- | --- |
| A voice agent integration for calls, web chat, prompts, or cost reporting | Use `https://api.eigi.ai/v1/public`. Server-side clients send a Studio API key in `X-API-Key`. OAuth-authorized clients can send their OAuth access token in `Authorization: Bearer …`. |
| An application that talks to your personal Eigi | Enable the Developer API on the intended computer. Desktop uses a local address and a generated key. The hosted computer uses the base URL from Studio and a platform API key. [Connect your application](/eigi-agent/developer-api). |
| A voice client for a physical Eigi board | Pair the board in Studio, then use its device credential to request a one-time call token. [Board sign-in and voice sessions](/eigi-gadgets/device-api). |

## Make a first platform request

Open [API Keys in Studio](https://studio.eigi.ai/api-keys), create a key, and keep its value in a server-side environment variable named `EIGI_API_KEY`. You can check authentication and find a voice agent with one read-only request.

```bash
curl --fail-with-body 'https://api.eigi.ai/v1/public/agents?page_size=1' \
  -H "X-API-Key: $EIGI_API_KEY"
```

A successful response contains `agents`, `page`, and `total`. An empty list means no agents matched. Create one in Studio or with [Create agent](/api-reference/public/agent-create). A `401` means you should check the credential and header. A `403` on an agent-specific request means you should check access to that agent.

## Choose your next request

- [Send a chat message](/api-reference/public/chat-send-message) to a Studio voice agent, or [call your personal agent](/eigi-agent/developer-api) with an OpenAI-compatible client.
- [Start an outbound phone call](/api-reference/public/outbound-call), [join a Daily room](/api-reference/public/daily-session), or [start a WebSocket device session](/api-reference/public/websocket-session).
- [Find a conversation](/api-reference/public/list-conversations) or [review account costs](/api-reference/public/cost-breakdown).

Each endpoint documents its own response shape. For example, agent listing returns a JSON object, streaming chat returns text, and device session creation returns short-lived connection credentials.
